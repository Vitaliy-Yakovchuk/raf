# Стадія hotfix

Виправ доручений дефект за core/process/test-first: спочатку регресійний тест, потім виправлення. Тип не дає права змінювати flow.

Для unit-регресії сам прожени початкове падіння: `raf_command test run --project <project> --phase red --group <change>/<unit-group> --files <file>`, потім підтвердь виправлення з `--phase hotfix`; наступні файли додай до того самого списку `--files`, або використовуй налаштовану групу без `--files`. Setup/import failure не є red. Для unit-прогонів керуйся core/process/unit-test-runs і projects/raf/test-runs. Зберігай стабільну `--group <change>/<unit-group>` та агрегат переданого red між агентами, фазами, SHA й оптимізацією відбору; не перейменовуй групу й не змінюй QA HOME для скидання лічильника.

У sandbox використовуй переданий `raf_command test run` лише коли він дозволений у `raf_subcommands`, однією простою командою без env-префікса, cd, конвеєрів, підстановок чи shell-обгорток. Фаза й відбір мають відповідати авторизованому дорученню. Не обходь sandbox і не повторюй невідомий результат сліпо.

Збережи повний незмінений JSON `TestRunResult`, stderr і код CLI окремо від child exitCode. У звіті дай посилання на доказ із командою, SHA/незакоміченими змінами workspace, runId, відбором, outcome, cleanup/timeout, knownRed/unexecuted/unknown і станом групи/наступною дією; відсутній або урізаний результат не є pass.

Виконуй лише вибрані пункти з доручення. Передай результат у JSON за шляхом і схемою доручення; стан tasks.md має відповідати фактичним результатам.

Чужу unit-регресію запускай у фазі hotfix лише за декларацією вибраного item; правило — conf/briefs/README.md, абзац «Чужу unit-регресію».
