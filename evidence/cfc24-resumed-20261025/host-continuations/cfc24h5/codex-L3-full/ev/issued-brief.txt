# Пам’ятка raf

Доступний префікс: node /tmp/raf-lfc-EsrHsv/orchestrator/raf-develop/bin/raf.ts. Використовуй адресний ID agent_id; session_name та внутрішній ID tmux не є адресою одержувача. Приклади показують форму виклику, не надають додаткових повноважень. Значення в <…> визнач перед виконанням; адресата знайди через agent ps.

- agent message: Передати повідомлення агенту з перевіреним відправником.
  --to (обов’язковий, одиничний): Адреса одержувача з ps.
  --text (обов’язковий, одиничний): Текст повідомлення.
  Приклад форми: node /tmp/raf-lfc-EsrHsv/orchestrator/raf-develop/bin/raf.ts agent message --to '<адреса-з-agent-ps>' --text 'Доручення launch-failure-fixture:1.1: повідомлення про результат або перетин.'
  Help: node /tmp/raf-lfc-EsrHsv/orchestrator/raf-develop/bin/raf.ts help agent message (або node /tmp/raf-lfc-EsrHsv/orchestrator/raf-develop/bin/raf.ts agent message --help).
  prerequisites: Адресу одержувача отримано через agent ps; відправник перевірений та має право доставки.
  sideEffects: Доставляє текст активному адресату через його адаптер; receipt підтверджує доставку за контрактом каналу.
  output: JSON receipt; exit 0 лише для підтвердженої доставки.
  errors: Ненульовий код із errorCodes та JSON code/message/details/remediation. За часткового виконання перевірте completed/pending і retrySafe перед повтором; довідка: raf help agent message.
  Деталі за потреби: /tmp/raf-lfc-EsrHsv/orchestrator/conf/raf-constants.json#/commands/1; параметри, valueSources й контракт agent message при помилці або уточненні виклику.

- agent ps: Показати активних агентів після звірки процесів.
  Приклад форми: node /tmp/raf-lfc-EsrHsv/orchestrator/raf-develop/bin/raf.ts agent ps
  Help: node /tmp/raf-lfc-EsrHsv/orchestrator/raf-develop/bin/raf.ts help agent ps (або node /tmp/raf-lfc-EsrHsv/orchestrator/raf-develop/bin/raf.ts agent ps --help).
  prerequisites: Доступ до ізольованого/робочого SQLite відповідно до покоління raf та перевірені OS identity.
  sideEffects: Звіряє процеси й поточні сесії, обробляє прийняті результати та належні завершення; не запускає нових агентів.
  output: JSON поточних сесій з адресними ID, activity, process та observation; адресою є addressId.
  errors: Ненульовий код із errorCodes та JSON code/message/details/remediation. За часткового виконання перевірте completed/pending і retrySafe перед повтором; довідка: raf help agent ps.
  Деталі за потреби: /tmp/raf-lfc-EsrHsv/orchestrator/conf/raf-constants.json#/commands/2; параметри, valueSources й контракт agent ps при помилці або уточненні виклику.

- test run: Запустити адресну unit-групу або integration-сценарій (фаза integration) за політикою фази.
  --project (обов’язковий, одиничний): Зареєстрований проєкт.; значення: etchly, stitchly, crm, company, invite, vitaliy-page, ramus-enterprise, shared-libs, dash, ramus-cloud, raf, orchestrator
  --phase (обов’язковий, одиничний): Фаза прогону.; значення: main, hotfix, spec, design, test-scaffold, implement, coordinator, qa, context-review, red, integration
  --group (обов’язковий, одиничний): Стабільна група <change>/<group>: unit-група або точний preset integration-сценарію.
  --files (необов’язковий, повторюваний): Точні відносні файли групи одним списком після одного --files (прапорець не повторювати).
  --only (необов’язковий, повторюваний): Лише knownRed IDs у форматі file::name; для integration-профілю не дозволено.
  Приклад форми: node /tmp/raf-lfc-EsrHsv/orchestrator/raf-develop/bin/raf.ts test run --project 'raf' --phase 'implement' --group '<group>'
  Help: node /tmp/raf-lfc-EsrHsv/orchestrator/raf-develop/bin/raf.ts help test run (або node /tmp/raf-lfc-EsrHsv/orchestrator/raf-develop/bin/raf.ts test run --help).
  prerequisites: Активна зміна, налаштований профіль, перевірене робоче дерево та ізольований QA HOME для raf-develop/hotfix.
  sideEffects: Адресний процес unit- або integration-тестів, його дерево та активний агрегат SQLite вибраного HOME; без історії прогонів.
  output: JSON TestRunResult з testKind, timeoutPolicy і callerPhase; код 0 лише для passed.
  errors: Ненульовий код для refused, setup-failed, assertions-failed, timed-out, interrupted та unverified-remainder.
  Чужа unit-група доступна implement/qa/hotfix лише за кінцевою декларацією `; regressionGroups=["change/group"]` вибраного item і довіреним launch snapshot із sourceChange/sourceItem та preset profileId/files. Фаза/project/workspace/branch незмінні; без --files діє preset, явні files і файли --only — лише його піднабір, самі IDs — knownRed цільової групи. Drift preset або неактивна ціль потребує нового перевіреного запуску. Використовуй той самий агрегат/QA HOME цільової групи; дозвіл не розширює assignment.changes, звітні items, файлові права чи права test-scaffold. У доказі назви source item і цільову групу. Стару сесію без grant або недоступний канал передай main через agent message з точною командою; до готовності довіреного каналу регресію виконує main за чинною політикою red.
  Деталі за потреби: /tmp/raf-lfc-EsrHsv/orchestrator/conf/raf-constants.json#/commands/6; параметри, valueSources й контракт test run при помилці або уточненні виклику.

При помилці збережи ненульовий код виходу, прочитай причину, received/expected, completed/pending і remediation; звернись до адресного help. Перед повтором врахуй побічні дії. Невідоме не видавай за встановлене; failed не перетворюй на succeeded. Не друкуй секрети, сирі великі логи або весь бриф. Розбіжність help і каталогу передай main для виправлення, без локального alias. Help не запускає агентів і не збирає зовнішні квоти.

# Адресний покажчик джерел

Читай зараз лише явно призначені предметні вимоги з усіма сценаріями й застосовні обмеження стадії. Умовні деталі читай тільки за вказаним тригером; покажчик не вимагає читати всі адреси.

Точні предметні адреси, секції/вимоги, причини й умови читання наведено один раз у sources конкретного доручення нижче. Якщо предметний контракт там не визначений, уточни його за вибраними пунктами tasks.md і proposal.md; не читай усі design/delta.

Результат передай атомарним JSON за report_path/report_schema; повідомлення в чаті його не замінює.

Окремі файли поза дозволеними теками: ["/tmp/raf-lfc-EsrHsv/orchestrator/questions/projects/raf/questions.md"]. Змінюй їхній вміст через shell-команду в пісочниці, відкриваючи сам файл для запису на місці (in-place), наприклад Node fs.writeFile або Python open/Path.write_text. Вбудований apply_patch не має native дозволу на ці окремі файли; запис через тимчасовий сусідній файл і rename, unlink або атомарну заміну не підтримується. Відмова apply_patch не потребує approval чи розширення доступу: використовуй shell-запис самого файла. Батьківські теки й сусідні файли не отримують дозволу на запис. JSON-звіт записуй атомарно за report_path у власній дозволеній теці запуску.

Звіт обов’язково містить commits: [{repository: string, sha: string}]. Кожний запис має рівно repository — дослівний канонічний корінь дозволеного репозиторію — та sha — повний lowercase Git commit OID. Укажи всі власні коміти роботи, доказів і завершення в ancestry-порядку всередині кожного репозиторію, включно з фінальними комітами архівації; checkboxCommits raf не додавай. Дозволені репозиторії: ["/tmp/raf-lfc-EsrHsv/orchestrator/raf-develop","/tmp/raf-lfc-EsrHsv/orchestrator"]. Якщо власних комітів немає, запиши commits: [] та поясни причину в answer. Не використовуй скорочені SHA, refs, рядковий legacy-масив або додаткові поля записів.

# Конкретне доручення

Працюй лише над дорученими пунктами. Відповідай власнику українською. Зберігай правдиві результати й докази; галочки доручення ставить raf. Запиши JSON за report_path та report_schema. Коротко заповни context: unnecessary (source, reason) і missing (description, foundAt); порожні масиви допустимі. Для узгодження з іншими виконавцями виконуй лише `raf_command agent message …` і `raf_command agent ps …` і `raf_command test run …` окремою простою командою, без cd, конвеєрів, підстановок і змінних перед нею: лише такі команди виконуються поза пісочницею й мають доступ до стану raf; інших команд raf не виконуй. Після перевірок сам закоміть свої зміни до JSON-звіту: додавай до коміту лише власні шляхи, чужі незакомічені правки в тому самому дереві не чіпай і не комітуй, перетини й спільні незакомічені файли узгоджуй з іншими виконавцями за projects/orchestrator/parallel-development «Коміти в спільному робочому дереві». Зайнятий індекс очікуй, чужий index.lock не видаляй. Обов'язок закомітити свою роботу входить у доручення; хеші створених комітів вкажи у звіті (поле commits). Push не виконуй: `git push` дозволено лише окремим дорученням, push визначає main.
