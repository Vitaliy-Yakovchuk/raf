# Runner claude

Ця частина призначена для CLI `claude`, запущеного raf через tmux. Модель і effort уже обрані raf; не замінюй їх самостійно. Використовуй доступні інструменти цього CLI для дорученої роботи. Підсумкова відповідь у чаті не замінює JSON за `report_path` і `report_schema` з доручення. Формат запуску, доставки й продовження визначає адаптер CLI, а не текст цього брифа.


# Стадія design

Підготуй або онови UI/UX і макети для доручених сценаріїв відповідно до застосовних специфікацій дизайну.

Виконуй лише вибрані пункти з доручення. Передай результат у JSON за шляхом і схемою доручення; стан tasks.md має відповідати фактичним результатам.

# Пам’ятка raf

Доступний префікс: node /tmp/raf-lfc-vUnyKK/orchestrator/raf-develop/bin/raf.ts. Використовуй адресний ID agent_id; session_name та внутрішній ID tmux не є адресою одержувача. Приклади показують форму виклику, не надають додаткових повноважень. Значення в <…> визнач перед виконанням; адресата знайди через agent ps.

- agent message: Передати повідомлення агенту з перевіреним відправником.
  --to (обов’язковий, одиничний): Адреса одержувача з ps.
  --text (обов’язковий, одиничний): Текст повідомлення.
  Приклад форми: node /tmp/raf-lfc-vUnyKK/orchestrator/raf-develop/bin/raf.ts agent message --to '<адреса-з-agent-ps>' --text 'Доручення launch-failure-fixture:1.1: повідомлення про результат або перетин.'
  Help: node /tmp/raf-lfc-vUnyKK/orchestrator/raf-develop/bin/raf.ts help agent message (або node /tmp/raf-lfc-vUnyKK/orchestrator/raf-develop/bin/raf.ts agent message --help).
  prerequisites: Адресу одержувача отримано через agent ps; відправник перевірений та має право доставки.
  sideEffects: Доставляє текст активному адресату через його адаптер; receipt підтверджує доставку за контрактом каналу.
  output: JSON receipt; exit 0 лише для підтвердженої доставки.
  errors: Ненульовий код із errorCodes та JSON code/message/details/remediation. За часткового виконання перевірте completed/pending і retrySafe перед повтором; довідка: raf help agent message.
  Деталі за потреби: /tmp/raf-lfc-vUnyKK/orchestrator/conf/raf-constants.json#/commands/1; параметри, valueSources й контракт agent message при помилці або уточненні виклику.

- agent ps: Показати активних агентів після звірки процесів.
  Приклад форми: node /tmp/raf-lfc-vUnyKK/orchestrator/raf-develop/bin/raf.ts agent ps
  Help: node /tmp/raf-lfc-vUnyKK/orchestrator/raf-develop/bin/raf.ts help agent ps (або node /tmp/raf-lfc-vUnyKK/orchestrator/raf-develop/bin/raf.ts agent ps --help).
  prerequisites: Доступ до ізольованого/робочого SQLite відповідно до покоління raf та перевірені OS identity.
  sideEffects: Звіряє процеси й поточні сесії, обробляє прийняті результати та належні завершення; не запускає нових агентів.
  output: JSON поточних сесій з адресними ID, activity, process та observation; адресою є addressId.
  errors: Ненульовий код із errorCodes та JSON code/message/details/remediation. За часткового виконання перевірте completed/pending і retrySafe перед повтором; довідка: raf help agent ps.
  Деталі за потреби: /tmp/raf-lfc-vUnyKK/orchestrator/conf/raf-constants.json#/commands/2; параметри, valueSources й контракт agent ps при помилці або уточненні виклику.

При помилці збережи ненульовий код виходу, прочитай причину, received/expected, completed/pending і remediation; звернись до адресного help. Перед повтором врахуй побічні дії. Невідоме не видавай за встановлене; failed не перетворюй на succeeded. Не друкуй секрети, сирі великі логи або весь бриф. Розбіжність help і каталогу передай main для виправлення, без локального alias. Help не запускає агентів і не збирає зовнішні квоти.

# Адресний покажчик джерел

Читай зараз лише явно призначені предметні вимоги з усіма сценаріями й застосовні обмеження стадії. Умовні деталі читай тільки за вказаним тригером; покажчик не вимагає читати всі адреси.

Точні предметні адреси, секції/вимоги, причини й умови читання наведено один раз у sources конкретного доручення нижче. Якщо предметний контракт там не визначений, уточни його за вибраними пунктами tasks.md і proposal.md; не читай усі design/delta.

- /tmp/raf-lfc-vUnyKK/orchestrator/conf/raf-constants.json#/reportStatuses — лише статуси під час запису звіту за переданою report_schema.

- /tmp/raf-lfc-vUnyKK/orchestrator/openspec/specs/projects/orchestrator/autonomous-development/spec.md — «Аудит та вилучення неактуальних змін», коли виявлено суперечність; «Архівація останнім виконавцем» і skip_specs, коли закрито всі пункти всієї зміни.

- /tmp/raf-lfc-vUnyKK/orchestrator/openspec/specs/projects/orchestrator/parallel-development/spec.md — «Коміти в спільному робочому дереві» зі сценаріями; читати зараз перед власним комітом або при перетині файлів.

Фактичний робочий каталог cwd: /tmp/raf-lfc-vUnyKK/orchestrator/raf-develop. Корінь OpenSpec root: /tmp/raf-lfc-vUnyKK/orchestrator. Передумови й критерії перевірки/очікуваний результат визначені в outcome та вибраних пунктах нижче; відсутні конкретні передумови уточни перед залежною дією. Результат передай атомарним JSON за report_path/report_schema; повідомлення в чаті його не замінює.

Звіт обов’язково містить commits: [{repository: string, sha: string}]. Кожний запис має рівно repository — дослівний канонічний корінь дозволеного репозиторію — та sha — повний lowercase Git commit OID. Укажи всі власні коміти роботи, доказів і завершення в ancestry-порядку всередині кожного репозиторію, включно з фінальними комітами архівації; checkboxCommits raf не додавай. Дозволені репозиторії: ["/tmp/raf-lfc-vUnyKK/orchestrator"]. Якщо власних комітів немає, запиши commits: [] та поясни причину в answer. Не використовуй скорочені SHA, refs, рядковий legacy-масив або додаткові поля записів.

# Конкретне доручення

Працюй лише над дорученими пунктами. Відповідай власнику українською. Зберігай правдиві результати й докази; галочки доручення ставить raf. Запиши JSON за report_path та report_schema. Коротко заповни context: unnecessary (source, reason) і missing (description, foundAt); порожні масиви допустимі. Для узгодження з іншими виконавцями виконуй лише `raf_command agent message …` і `raf_command agent ps …` окремою простою командою, без cd, конвеєрів, підстановок і змінних перед нею: лише такі команди виконуються поза пісочницею й мають доступ до стану raf; інших команд raf не виконуй. Після перевірок сам закоміть свої зміни до JSON-звіту: додавай до коміту лише власні шляхи, чужі незакомічені правки в тому самому дереві не чіпай і не комітуй, перетини й спільні незакомічені файли узгоджуй з іншими виконавцями за projects/orchestrator/parallel-development «Коміти в спільному робочому дереві». Зайнятий індекс очікуй, чужий index.lock не видаляй. Обов'язок закомітити свою роботу входить у доручення; хеші створених комітів вкажи у звіті (поле commits). Push не виконуй: `git push` дозволено лише окремим дорученням, push визначає main. Репозиторії коміту: /tmp/raf-lfc-vUnyKK/orchestrator (Orchestrator: /tmp/raf-lfc-vUnyKK/orchestrator).
