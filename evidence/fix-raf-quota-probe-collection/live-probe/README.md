# Grok probe: фактичний екран 80×24

Попередній фікс `57d00f1dd54650783455d299b8efb9d587424583` залежав від рекламного рядка `Grok 4.7 is here!`. Production transport запускає pane 80×24; живий Grok 1.0.70 натомість показав `New /learn skill!` і `Grok Build 1.0.70` у footer. Порожній framed composer уже готовий до `/usage`, але probe зупинявся на `unknown_screen`.

`before/frames.json` — справжнє відтворення через production entry та transport у синтетичному зареєстрованому workspace, з окремим QA HOME/state/tmp. `grok-1.0.70-startup-80x24.txt` — незмінений текст непорожнього кадру з цього відтворення. Unit-регресія на цьому кадрі спочатку впала; після виправлення вся налаштована unit-група пройшла (70 тестів).

Фікс розпізнає ідентичність Grok Build та порожнє поле вводу в рамці незалежно від рекламного тексту. Непорожній composer і сторонній CLI не розпізнаються як цей стартовий стан; наявна перевірка точного пункту `/usage` перед Enter збережена.

`after/` та `after-2/` — два успішних живих виклики production `runner limits --runners grok`, а не мок CLI. Обидва зберегли достовірну повну квоту 14% used / 86% remaining, reset 2026-11-07 16:58 UTC. У цих двох запусках Grok випадково показав попередню рекламу; новий `/learn` варіант перевірено фактичним кадром у unit-регресії. Нативна панель підтвердила відсутність модельних викликів (`no model calls yet`). Probe-сесії прибрано production transport, додатково прибрано власний тестовий server і fixture. Робочі сесії raf не використовувались.

`verification.json` містить команди, базовий SHA, хеші незакомічених файлів, точний відбір, runId, outcome, CLI exit code окремо від child exitCode, cleanup/timeout, knownRed/unexecuted/unknown та стан/наступну дію групи. Початковий hotfix unit-прогін також збережений: він виявив помилку негативної fixture (`replace` замість `replaceAll` для двох згадок Grok Build); виправлено саме fixture без зміни очікуваної поведінки.

У кожній підтеці прогону `TestRunResult.json` зберігає повний незмінений JSON із каналу, `cli-exit-code.txt` — код CLI, `stderr.txt` — весь не-JSON суфікс каналу (включає warnings та службовий рядок шляху результату), `tool-result.json` — повну відповідь інструмента. Обрізання немає. `cli-result.json` — результат внутрішнього production CLI, окремо від TestRunResult wrapper-а. Email і токени не зберігаються; credentials не копіюються, Grok використовує свій наявний GROK_HOME, тоді як HOME і стан raf ізольовані.

Зміни конфігурації групи автоматично закомічені raf до кореневого репозиторію; SHA цих чужих auto-комітів не включається до власних commits звіту. Активація main та пункт 1.2 не належать цьому виконавцю.
