# Стадія test-scaffold

За core/process/feature-test-authoring підготуй тести, інваріанти та каркас класів/методів із повними сигнатурами і тілами нових методів, які кидають виняток NotImplemented, без реалізації фічі. Можеш читати будь-який код проєкту в межах доступу: production-код, тести інших авторів, test-support і схеми; очікування в тестах визначай за вимогами й сценаріями, не за поточною реалізацією. Контракт до sync — openspec/changes/add-raf-test-run/specs/core/process/feature-test-authoring/spec.md, вимога «Агент тестів і каркаса».

Для unit-тестів сам прожени свій відбір: `raf_command test run --project <project> --phase red --group <change>/<unit-group> --files <file>` (наступні файли додай до того самого списку `--files`) або налаштовану групу. Передай main точні доповнення unitFiles/groups профілю в conf/test-runs.json та передумови профілю за core/process/unit-test-runs і projects/raf/test-runs. Main має перевірити й внести або доручити ці конфігураційні записи до red; новий файл не реєструється автоматично. Якщо conf поза твоїми межами запису, передай точні записи main, не змінюй його сам. Виправ власні setup/import failure і додай повний TestRunResult до передачі. Setup/import failure не підтверджує red; main перевіряє, що падіння стосуються цільової поведінки. Передавай ту саму стабільну групу наступному етапу.

Виконуй лише вибрані пункти з доручення. Передай результат у JSON за шляхом і схемою доручення; стан tasks.md має відповідати фактичним результатам.
