# fix-raf-hotfix-activation-conf-churn:1.1

Defect: hotfix activation refused with «Hotfix snapshot fingerprint changed» whenever agents registered test groups in `conf/test-runs.json` during the ~10 minute gates, because the snapshot configuration fingerprint hashed the whole `conf/` byte-for-byte while auto-commits «conf: agent test group registrations» only touch `projects/*/groups`.

Fix: `configurationInventory`/`configurationDigest` in `src/hotfix-host.ts` digest `conf/test-runs.json` without the `projects/*/groups` registrations (every other key and every other conf file stays byte-exact). Both the hotfix snapshot (`src/hotfix-activation.ts`) and the main slot fingerprint (`src/main-symlink-storage.ts`) use the shared inventory, so a registration between gates or between preparation and switch no longer changes any compared fingerprint, while a change of `conf/raf.json`, `conf/models.json`, test-run profiles or any other configuration still invalidates the proof.

Test: `test/hotfix-activation-conf-churn.test.ts` — a regression gate that registers a group, then another registration after green, then activation succeeds and the registry stays in `configuration`; `conf/models.json` or `projects/raf/profiles` changes after green still refuse. Existing assertions compare the registry entry through `configurationDigest`.

Evidence files: each `*.TestRunResult.json` is the complete unchanged JSON returned by raf; `*.stderr.txt` is the CLI stderr (warnings about unrelated etchly registrations and Dash); `runs.json` indexes command, SHA, uncommitted state, runId, selection, outcome, exit codes, cleanup/timeout, knownRed/unexecuted/unknown and group state. The stable group `fix-raf-hotfix-activation-conf-churn/conf-churn` and QA HOME were kept throughout; no counter reset.
