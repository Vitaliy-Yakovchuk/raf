# Z.464 — очікування activation lock

Актуальність перевірено за proposal Why/What Changes, tasks.md Z.464, workspace-routing «Перевірений hotfix активується цілісно», core/process/test-first, unit-test-runs та projects/raf/test-runs. Пункт залишається відкритим і дефект наявний: `locked()` використовував мінімальний runner transitionMs як строк відмови. Поточний код Z.461 використовує той самий lock, тому виправлення потрібне також для symlink main. Переносимі processStart/reaper від Z.461 вже закомічені 42ac8dbd8737fa50c2e8a0680dec0941fd9c693a; activation.ts не змінювався цим виконавцем.

Застарілий Z384.S03 вимагав відмову за таймаутом; актуальне доручення Z.464 та main через agent message погодили замінити його регресією20. Z384.S05 тепер очікує першу колізію, а появу intent передає filesystem event, без вимоги повторного polling. Фікстура отримала обов’язкові для чинного коду develop route та runtimeInventory; твердження про цілісність покоління не послаблені.

Регресія запускає20 конкурентних викликів реального acquireHotfixReader (startup admission для CLI/agent run) на ізольованій файловій фікстурі. Усі натрапляють на зайнятий lock; Date.now пересувається за чинний transitionMs, після чого власник звільняє lock. Початковий red:20 помилок Hotfix activation lock timeout, ERR_ASSERTION, не setup/import. Після фіксу всі20 отримують унікальні leases одного цілісного покоління та звільняють їх. Це unit-перевірка startup admission;20 живих native runner/agent run не запускалися.

`fs.watch` реєструється до claim, тому звільнення між невдалим claim і початком await не губиться. Події activation.lock/intent.json будять повторну перевірку; prepared/released тимчасові каталоги не викликають зайвих claim. Часової відмови і polling кожні10ms більше немає. Чинний transitionMs використовується як інтервал warning/liveness, без нового числового параметра: одне попередження, очікування триває; періодична перевірка start identity дозволяє reclaim власника, який помер без filesystem event. Валідація identity, intent refusal, серіалізація та власне звільнення lock збережені.

Повні незмінені TestRunResult у red.result.json/hotfix.result.json, stderr окремо, CLI exit окремо від child exitCode. Transport збережено без обрізання. Workspace SHA, всі незакомічені шляхи та релевантний patch зафіксовано перед кожним прогоном. Обидва прогони використовували однакові group та QA HOME; timeoutCount0. Hotfix:16/16 passed, cleanup complete, knownRed/unexecuted/unknown порожні, groupState=complete, nextAction=complete. Додатково diff --check пройшов. Незмінені тести Z426 у тому самому відборі перевіряють release race, чужого власника та callback errors activation/writer locks.

Реєстрацію complete-raf-flow-contracts/z464 у conf/test-runs.json зроблено in-place за домовленістю; коміт конфігурації виконує main. tasks.md виконавець не змінює. У зміні лишаються інші відкриті пункти, тому sync/archive не виконується. Активація та перенесення в develop належать main і цим unit-результатом не підтверджуються.
