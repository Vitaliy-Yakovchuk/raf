# QA 7.2: stderr тесту та службовий stderr CLI

Після відмови звіту main перевірив брокер: для переданих runId/group/phase/selection/CLI записи збігаються, а stderrDigest тесту дорівнює SHA-256 порожнього потоку. Main доручив зберегти службові повідомлення старої CLI окремо і послатися на stderr тесту, без повторних прогонів.

`separate.py` перевірив усі 16 унікальних stderr-посилань регресій звіту. Архіви містять лише 17 JSON-рядків `kind=launch-queue.waiting`, кожен із testRunId відповідного незміненого TestRunResult. Інших байтів stderr немає. Assertion-діагностики red містяться в TestRunResult і збережені повністю.

- `*.cli.stderr` — точні копії початкових stderr-файлів зі службовими рядками CLI.
- `*.test.stderr` — порожній stderr тесту після відокремлення виключно цих службових рядків.
- `index.json` — відповідність runId, команд, відбору, початкових і нових шляхів, SHA-256, CLI/child exit code, cleanup/timeout, knownRed/unexecuted/unknown та стану групи. SHA й незакомічені правки на момент прогону залишаються в початкових каталогах доказів, названих `workspaceEvidenceDirectory`.

Межа доказу: це відокремлення збереженого виводу CLI за типом кожного рядка та підтвердженням main щодо брокера, а не новий запис child stream. Скрипт не читає брокер і не заявляє самостійної перевірки його записів. Остаточне зіставлення виконує валідатор звіту raf. Початкові stderr і TestRunResult не змінено; тестів не перезапущено, помилок не приховано. Якщо з'явиться будь-який рядок іншого типу чи runId, скрипт відмовить замість його видалення.

## Виправлення за адресною перевіркою брокера

Попередній висновок про порожній stderr усіх 16 прогонів був надмірним: тип `launch-queue.waiting` сам по собі не доводить, який потік зберіг брокер. Main підтвердив прийняття findings 0..7 із відокремленим порожнім потоком, але для шести новіших runId 570b763f/69e08120, b17472a5/1552a255, db1cbc01/ce66146d назвав непорожні SHA. Кожен точно збігається з початковим незміненим stderr. Для цих шести прогонів звіт знову посилається на початковий файл; його службові рядки не видаляються. `index.json.reportStderrPath` визначає чинне посилання, `brokerStderrSha256ReportedByMain` — наданий main SHA. Порожні похідні файли для цих шести збережено лише як історію помилкового відокремлення, вони не є доказом stderr цих прогонів.
